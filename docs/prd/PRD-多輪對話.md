# PRD:多輪對話(接續追問)

> 狀態:草稿
> 關聯 Issue:#2
> 日期:2026-09-05

## 背景(為什麼要做)

老師回饋(1150903):系統只能處理獨立問題。使用者問「A、B 有什麼區別」得到答案
1、2、3 後,接著追問「第 2 點的細節」,系統無法順著脈絡回答——因為目前程式每輪
只把「當下那一句」拿去檢索與回答,完全不帶對話歷史(`app.py` 的 `on_message`)。

實際案例:
- 詢問冥府審判相關故事 → 條列 1、2 → 無法根據條列接續回應
- 縮小到某條目後,追問條目內特定詞意 → 回應通用釋義而非該條目語境

## 目標

1. 使用者可用代名詞、序號接續追問(「第 2 個呢?」「他後來怎麼了?」),系統能正確接續
2. 追問時的向量檢索也要吃到上下文(不能拿「第 2 個呢?」直接去查向量庫)

## 不做什麼(Non-goals)

- 不做跨 session 的長期記憶(關掉分頁即重來)
- 不做使用者帳號綁定的個人化
- 不改變向量庫與語料(那是另一個 issue 的範圍)

## 方案概述

1. **對話歷史**:在 Chainlit `user_session` 保存本次對話的 (question, answer) 列表,
   組 prompt 時帶入(設上限,如最近 10 輪,防 token 爆量)
2. **問題改寫(query condensation)**:檢索前先用 LLM 把追問改寫成獨立完整問題
   (例:「第 2 個呢?」→「冥府審判故事中第 2 則的詳細內容」),再拿改寫後的問題查向量庫
   ——RAG 多輪對話的標準做法

## 驗收情境

| # | 操作 | 預期結果 |
|---|------|----------|
| 1 | 問「冥府審判相關故事有哪些?」→ 追問「第 2 個的詳細內容」 | 正確講出第 2 則對應條目的內容 |
| 2 | 縮小到某條目後追問條目內特定詞意 | 回答該條目語境下的意義 |
| 3 | 連續追問 3 輪以上 | 脈絡不斷裂 |
| 4 | 跑迴歸測試清單 B 組全部 | 全過 |

## 風險與備註

- 每輪多一次改寫呼叫,OpenAI 費用略增(改寫用 gpt-4o-mini 即可,增幅極小)
- 歷史帶太長會稀釋檢索品質,上限輪數要實測調整
