# ADR-0001:雲端部署架構選擇

> 狀態:已採用
> 日期:2026-07-27(補記)

## 背景

老師要求將前人開發的「夷問」部署上雲端,**不做任何功能改動**。
需要:公開網址、HTTPS、低維運成本、程式碼零修改。

## 考慮過的選項

1. **AWS Lightsail 主機 + Docker Compose**——沿用專案現成的 Dockerfile;
   與前案 ai-librarian 同平台,經驗可複用。缺點:固定月費、要自己管主機
2. **PaaS(Zeabur / Render / Railway)**——部署更簡單。缺點:免費層會休眠、
   與既有專案的維運經驗不一致
3. **AWS ECS / Cloud Run 等容器服務**——彈性佳。缺點:對單一小專案過度複雜

## 決定

- 主機:AWS Lightsail(東京,規格比照前案),以 repo 內建的 docker-compose 啟動
- 網域與 HTTPS:Cloudflare Registrar 購入 yijianzhi.org,DNS 代理(Proxied),
  SSL 模式 **Flexible**(訪客→Cloudflare 走 HTTPS;Cloudflare→主機走 HTTP:80)
- 伺服器上以 `docker-compose.override.yml` 將主機 port 80 對應到容器 8000
  (Cloudflare 代理不支援 8000 埠),**repo 檔案保持零改動**

## 理由

滿足「零功能改動」的硬性要求;Dockerfile 是現成的,部署面只需環境變數與埠對應;
HTTPS 交給 Cloudflare 自動簽發,主機端不需裝憑證與 reverse proxy,維運面最小。

## 後果

- 得到:程式碼原封不動即上線;主機重啟自動復活(compose restart policy)
- 放棄:Cloudflare→主機這段未加密(Flexible 模式)。若未來有敏感資料,
  應改 Full 模式並在主機端裝憑證(如 Caddy/certbot)
- 限制:服務綁在單一主機上,無自動擴展;對課程展示用途足夠
